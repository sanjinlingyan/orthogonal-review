# 一次完成的正交审查流程

## 1. 调度者准备

只在用户给定项目范围定位正式交付。支持 `R1/R2/R3/candidate` 或 `task/R1/R2/R3/candidate`，正式轮优先；实际版本或批次范围有多个候选时集中询问。不要读取 Review Gate 运行目录或历史报告。批次明确逐题路径，不能根据整个任务池推定本批缺交。

检查 candidate 是下游真正应收到的材料，若含参考答案、未来轮材料或隐藏评分材料，保留发现并停止该题盲实作，记录限制。不能偷偷删除输入后把修改版称为原提交。流程不需要加载合同条款库或既有 Gate 规则。

运行 `run`，读取私有 `_internal/state.json` 中题目 key。逐题顺序处理。建立可用专业环境；预算、时限由当前平台及任务的已授权条件约束，记录实际限制，不凭空设难度门槛。没有可执行环境时用 `limit` 说明具体欠缺并继续能做的工作。

## 2. 全新会话与逐轮实作

用平台的无历史继承机制启动执行者，首次仅要求它回报会话身份并等待任务。保存平台真实启动回执（可为返回文本的原样文件），建立 actor JSON；`fresh_context=true` 是有回执支持的调度声明，不是代码自动证明。

调用 `handoff --role executor`，给该会话 packet 路径。将可访问目录限定为 packet，专业工具按授权提供；无法进行操作系统级隔离时如实记录实际访问约束，不声称已经强隔离。平台回执保存在调度侧，不放入 candidate。

执行者读 prompt.md 和 packet.json，自行解释任务、查看附件并实际完成输出。调度者不提供领域答案。把澄清问题记入本轮结果；如果缺信息导致无法推进，保存 blocked 和现场，不替作者即席补全。提交后工具冻结输出。

完成一轮后，同一会话再次 handoff 自动获得下一轮输入及已冻结的真实 parent。不得从参考交付填补前轮；前轮 failed/blocked 时停止后续实作，后续轮次记 unknown。不得预读未来轮来规划答案。

## 3. 独立检查产物

实作结束或阻塞后，创建第二个全新会话并 handoff reviewer。只给检查工作空间及审查提示；不提供执行者总结、Gate 结论、原判或期望结果。

检查者从实际用户目标和输入建立本题可用条件，实际打开、重算、运行、编辑或测量原生产物，并在 checks 保存独立探针。对已经完成的轮次分别检查职责、结果、可继续使用性及后轮衔接。对未执行轮给 unknown 与原因。使用 source 值和独立推导核结果，不能把存在文件、退出码 0 或执行者自述当作可用证明。

每项发现记录问题、位置、现场证据、原因分类、确信程度、修复动作与验证条件。任务缺陷需要输入缺漏、不可消解冲突、依赖断链等直接证据。只看到一次错误产物，首先属于执行结果观察，不能直接确认 task_material。

## 4. 一次诊断及归因

首次执行失败或审查发现不可用/未确定时，可创建第三个全新会话 diagnostician。它读取已经冻结的任务和实作现场，自行定位并尝试失败部分，最多一次；不继承第二位审查者的结论。新的产物和探针写入自己的 output/checks，不能修改首次输出。

独立诊断成功说明至少存在可行做法，可支持把首次失败归为执行或能力问题；不自动把首次整条链改成成功。多次失败仍不能单靠次数证明题目坏。若独立意见冲突，保留双方证据和 unknown，不能投票或挑好结果。

## 5. 交付

收齐能做的角色结果，记录未能完成的具体条件，调用 finalize。工具核对原始材料、冻结输入/输出、证据和实现版本，生成两份报告。缺环境或独立会话不妨碍输出未知结论报告，但不能声称完成独立实作。

人类报告先呈现业务发现和真实执行范围。修复单区分任务缺陷、环境条件、执行者问题和待证实问题，不把 Agent 能力问题强制改成降低任务难度。补材料或修改版本后重新开始，旧记录保持原样。
