# 一次完成的正交审查流程

## 1. 定位和准备专业环境

调度者只在用户给定范围定位正式提交，支持 R1/R2/R3/candidate 或 task/R1/R2/R3/candidate，正式轮优先。不要读取 Review Gate、甲方历史反馈、评分或参考交付。candidate 含隐藏答案或未来轮泄露应记录为实际问题，不可偷偷删除再称原提交。

调度者可检查三轮材料以准备环境，但不得把未来轮或领域答案下发给执行者。创建 v2 运行，按实际工作声明覆盖三轮的能力需求。已有环境也须实际打开源文件、导入模型或执行专业测量，不只 import。用 environment 保存真实命令及探针；核心工具不代替模型审阅代码含义。

允许按用户授权配置本机必要免费工具，下载使用受信来源，记录版本；不自动购买许可证。缺环境应实际配置，失败后按日志修复并尝试可行替代，再运行真实能力 probe。同类错误不无限重复；仅许可证、权限或依赖取得失败等客观条件仍阻断时，可关联 configure、repair 以及最后失败 probe 的冻结回执标未审查。不满足回执条件不能 finalize。

## 2. 全新会话逐轮实作

用平台无历史继承机制创建全新执行会话，先回报身份并等待。保存真实启动回执、actor JSON。环境就绪后 handoff；执行者只读本轮 input 与自己真实 parent，不看未来轮、参考解或其他任务。普通文件夹不是安全沙箱，如实记录平台访问约束。

执行者自行解释任务、实际完成工作，最终文件放 output，探针放 checks，真实记录放 logs。完成需原生产物和证据。调度者不提供领域答案。逐轮 submit 冻结，再把下一轮 packet 给同一会话。前轮失败不能捏造父态跳轮。

开放角色遇环境缺口可补齐后继续，新增环境事件保留；冻结角色不能改写结果，重做应新建关联运行。不能把环境准备失败当作任务能力试验次数，也不能反复重试 Agent 挑出最好成绩。

## 3. 独立产物复核

创建另一位全新会话 reviewer，仅读 chain 与自己的检查文件，不给执行者总结、历史结论或期望答案。根据实际任务建立必要检查项，实际打开、重算、运行、编辑或测量原生工件。文件存在、退出码0、自述和文本坐标解析不能代替专业验证。

每轮列 checks：pass/fail/not_reviewed、直接证据与原因。失败需明确事实、归因、责任方、修复动作及复验条件。一次执行错误不是任务材料缺陷；环境问题归 review。缺证据先继续检查，不得草率交卷。只有已真实配置和排障但仍被阻断的环境项可 not_reviewed。

## 4. 一次独立诊断

必要时最多启动一次全新 diagnostician，仅读冻结任务与现场，不读 reviewer 判断；独立定位关键失败并实际探测。保留首次结果，诊断不覆盖首次结论；需要新实作链则关联新运行。意见冲突必须继续收集直接证据，不投票或挑有利结果。

## 5. 收口与交付

质量结论 pass/fail；完成状态 completed/incomplete 分开。必要项全部通过才 pass，任一已证实失败为 fail；没有失败但有客观环境阻断时 verdict=null、incomplete，显示未完成审查。存在失败并有未审查项时仍 fail/incomplete。未实作也无真实排障证据时禁止生成最终报告。

人类仅看结论、数量、逐轮简表与需处理事项，详情按需展开。Agent 单据分别列任务缺陷、实作问题及审查环境责任。真实资料留在仓库外；旧报告不能改写。
